## 1. 范围与兼容原则

本文只定义英雄与畸变系统，不修改已经完成的 v0.4.0 本地试玩基线。实现时应在新版本中增量扩展，确保关闭英雄与畸变后，现有 71 项测试仍全部通过。

规则优先级从高到低为：

1. 双方将帅死亡与直接死亡终局；
2. 英雄、畸变产生的路径击杀、陷阱和防御；
3. 暗子揭示、控制权变化与背刺；
4. 普通将军、裁决、无处可逃；
5. 回合切换与持续时间递减。

每局最多随机生效一项畸变。不同畸变之间不叠加，但畸变可以和双方英雄能力叠加。

## 2. 对局建立流程

规则引擎仍保留两个兼容开关，便于基础规则测试；当前产品入口固定同时开启英雄与畸变：

```ts
interface OptionalModeConfig {
  heroesEnabled: boolean;
  mutationsEnabled: boolean;
}
```

底层四种组合仍合法，但玩家实际进入的固定流程为：

`两人到齐 → 60 秒英雄选择 → 石头剪刀布 → 创建棋局并公开畸变 → 英雄入场 → 最多 60 秒英雄准备 → 红方行动`

### 2.1 英雄选择

- 两人到齐后立即开始 60 秒英雄选择；英雄选择发生在猜拳之前。
- 双方同时秘密选择；一方确认后，对方只能看到“已确定”，看不到英雄。
- 双方都确认后立即进入猜拳，但仍不公开对方英雄；允许相同英雄。
- 选择但未确认仍算未确认。倒计时结束时只为未确认玩家随机英雄，已经确认的选择保持不变。
- 超时随机结果向本人短暂展示约 0.8 秒，然后进入猜拳。
- 确认后不能更换。
- 英雄关闭时，不创建英雄选择阶段或英雄状态。

### 2.2 畸变抽取

- 猜拳确定先后手并创建正式棋盘时，最终规则先抽取普通、稀有、史诗、传说之一，再从该档候选中确定畸变。
- 普通、稀有、史诗、传说的精确外层概率尚未确定；当前运行时为保持可玩性，暂时继续从六项标准畸变中等概率抽取，不能把这一兼容逻辑视为最终概率。
- 若双方英雄解锁羁绊，对应宿命只作为隐藏候选加入传说内部池；它不创建第五种外层稀有度，也不改变外层传说概率。
- 已确认第一项宿命：诺兹多姆 × 姆诺兹多解锁 `end_time` / “时光之末”。其完整规则见本文 12A；当前 GitHub 检查点的宿命目录仍为空，因此该宿命**规则已确认但运行时未实现**。
- 除“时光之末”外，不得自行补写其他宿命 ID、英雄羁绊或效果。
- 使用服务器安全随机数；测试可注入固定随机源。
- 抽取结果和稀有度记录在公开房间状态中；进入棋盘后向双方播放同强度公布动画，只以颜色和文字区分四档。
- 顶部“本局畸变”只常驻显示名称；点击后才展示稀有度、简述和完整规则。
- 畸变关闭时使用 `null`，不得抽取后隐藏。

### 2.3 英雄入场与战斗准备

- 畸变公布后播放双方英雄约 2 秒的水墨入场；头像落入固定英雄位置后，才开始通用 `hero_preparation`。
- 战斗开始技能共用最多 60 秒的准备时间。没有战斗开始技能的英雄自动完成；所有需要操作的玩家完成后立即进入红方第一回合。
- 当前猎人在该阶段独立布置两个陷阱层；点击合法格点增加一层，再点同一点可叠层；“撤回上一步”删除最后一层草稿，“完成准备”锁定。
- 到时保留猎人已有草稿，由权威端在合法己方半场随机补齐剩余层并直接进入正式行棋。
- 双猎人可同时秘密布置。对方只能看到层数、使用次数、剩余时间和是否完成，不能获得未触发坐标。

建议房间阶段：

```ts
type RemoteRoomPhase =
  | "waiting"
  | "hero_selection"
  | "rps"
  | "hero_intro"
  | "hero_preparation"
  | "playing"
  | "finished";
```

`hero_intro` 等待双方完成本机入场动画；`hero_preparation` 由权威截止时间控制，普通走子在这两个阶段均被拒绝。

## 4. 英雄一：猎人——陷阱

### 4.1 布置

- 猎人在英雄入场后的 60 秒战斗准备中布置两个陷阱层。
- 只能布置在猎人自己的半场：红方 `y >= 5`，黑方 `y <= 4`。
- 可以放在已有棋子的脚下。
- 两层可以放在同一坐标。
- 猎人始终能看到自己的剩余陷阱；敌方在触发前看不到坐标和叠层数。

### 4.2 触发条件

一次行动成功落位后，同时满足以下条件才触发一层陷阱：

1. 落点存在敌方猎人的陷阱；
2. 该棋子在行动开始前由陷阱主人的敌方控制；
3. 移动、吃子和揭示完成后，该棋子仍由陷阱主人的敌方控制。

这两个控制权条件用于防止猎人用陷阱低成本鉴定己方暗子的真实身份。

被目标防御弹回原位不视为到达目标点，不触发目标点陷阱。路径击杀也不触发死者所在点或经过点的陷阱。

### 4.3 触发效果

- 一次进入只触发并消耗一层；同点剩余层继续存在。
- 陷阱直接杀死落点棋子，不属于“被棋子吃掉”。
- 普通防御、隐身和铁甲防御都不能阻止陷阱。
- 可以杀死敌方将帅；触发终局“伏击”。
- 双方都收到触发事件和播报：`猎物已踏入陷阱！伏击得手，红方／黑方获得胜利！`

### 4.4 持续时间与衰减

- 两层陷阱都属于可消耗资源；每触发一层就永久消耗一层。
- 前9个敌方正式走棋回合，未消耗陷阱保持完整致死效果。
- 敌方第9回合结算完成后，仍未消耗的剩余层进入衰减期。
- 第10、11、12个敌方正式走棋回合，剩余层改为控制陷阱：触发后不杀死棋子，而是使触发棋子在其控制方下一次回合中不能移动；该玩家仍可移动其他棋子。
- 控制陷阱触发后同样消耗该层。
- 第12个敌方正式走棋回合结算完成后，所有仍未触发的剩余层失效。
- 选英雄、猜拳、英雄入场、英雄准备、自动终结动画和战士额外应将均不计入上述敌方正式走棋回合。
- 实现和评分都必须按“当前剩余陷阱层数 + 当前寿命阶段”建模；如果两层都在前9回合触发，后续控制阶段没有陷阱价值。

## 5. 英雄二：潜行者——刺杀

### 5.1 次数与目标

- 潜行者英雄每局提供一次刺杀。
- “暗影之舞”畸变再向双方各提供一次刺杀。
- 潜行者遇到暗影之舞时最多使用两次，两个来源分别记录。
- 同一方同时只能维持一段刺杀潜行；上一段结束前不能开启下一次。
- 发动目标必须是己方控制的明棋，且不能是将帅。

### 5.2 发动行动

发动刺杀和首次走子属于同一个服务器原子命令：

```ts
interface AssassinationCommand {
  kind: "assassination";
  from: Position;
  to: Position;
  useStrongStrike: boolean;
  expectedRevision: number;
  actionId: string;
}
```

- 首次行动必须二选一：移动到合法空位并保留强击，或对合法目标立即强击并消耗强击。
- 必须遵守该棋子当前全部移动规则、畸变限制、堡垒和自陷将军规则。
- 两种首次行动完成后都进入隐身；立即强击分支进入隐身时不再拥有强击。

### 5.3 隐身

- 隐身状态和剩余回合向双方公开显示。
- 隐身持续到接下来的一个己方回合结束，不包括发动回合。
- 对方回合不消耗持续时间。
- 隐身棋子不产生攻击范围和将军。
- 不能被普通吃子或其他普通指向效果选择；刺杀强击可以选择并先移除其隐身。
- 不阻挡其他棋子的移动路径，不充当炮架、马腿或象眼。
- 所在格仍然被占用，其他棋子不能停在同一格。
- 陷阱、铁马碾碎和战车路径碾碎仍可将其杀死。

在下一个己方回合，玩家可以主动移动或吃子这枚棋：

- 行动开始后解除隐身；
- 可以在一次合法吃子上使用保留的强击；
- 不使用强击也会在行动完成后失去该次强击；
- 若该回合没有主动使用该棋，该回合结算后自动解除隐身并清除强击。

### 5.4 强击

- 强击沿用来源棋子的合法移动与吃子几何。
- 不能以将帅为目标。
- 可以选择正常不可被指定的隐身棋子。
- 目标先失去防御、隐身及其他可移除效果，再被直接杀死。
- 强击属于特殊吃子，触发吃子事件和死亡事件。
- 强击完成后攻击者落在目标点，随后照常结算陷阱。
- 首次行动立即强击后仍进入隐身；已经隐身的棋使用强击后结束本次隐身。

铁马与战车的“等同强击”只复用“清除效果并击杀”的结算模板，不消耗刺杀强击次数。

### 5.5 攻击战士防御

- 首次行动若选择攻击，必须使用强击，因此不会触发普通防御弹回。
- 隐身期间的后续普通攻击撞上防御时，目标消耗防御并存活，攻击者回到原位，同时解除隐身并失去未用强击。
- 使用强击则直接移除目标防御并杀死目标，不会被弹回。

## 6. 英雄三：战士——防护壁垒

### 6.1 普通防御的获得

- 每名战士最多让两枚不同的己方非将帅明棋获得普通防御。
- 触发条件：棋子在一步成功行动中从战士自己的九宫内部移动到九宫外部。
- 按实际成功触发的先后占用两个名额。
- 每个棋子一局最多获得一次；防御消耗、到期或棋子死亡都不返还名额。
- 将帅离开九宫不获得普通防御。
- 防御及剩余衰减状态向双方公开，并直接显示在棋面上。

基础规则规定暗子第一次移动后立即翻开；暗仕第一次又只能在九宫内移动。因此“暗子保持暗面离开九宫后才翻开并获得防御”在当前规则下不可到达，不进入实现。未来若新增“移动后仍不翻开”的效果，再重新定义该分支。

### 6.2 普通防御的效果

普通吃子命中带防御棋子时：

1. 消耗目标的一层防御；
2. 目标留在原位；
3. 攻击者返回行动前原位；
4. 本回合仍然结束；
5. 暗攻击者保持暗面，不读取或公开真实身份；
6. 不触发目标点、返回点陷阱或进入/离开区域效果。

路径碾碎、刺杀强击和陷阱不属于可被普通防御抵挡的攻击。

## 6G. 英雄十：死亡之翼——毁灭

类型：主动技能，每局一次。

### 发动窗口

- 只能在死亡之翼方自己的正式回合、尚未移动任何棋子之前发动。
- 无优势/劣势要求，无双方棋子数量要求。
- 每局最多发动一次。

### 毁灭结算

1. 锁定发动瞬间双方所有仍存活的非将/帅棋子。
2. 对锁定集合中的每一枚棋子分别进行一次独立50%毁灭判定。
3. 判定成功的棋子直接被摧毁；普通防御、隐身等效果不能阻止该摧毁。
4. 明棋、暗棋一视同仁；暗子被摧毁时按正常死亡规则公开真实身份。
5. 将/帅永远不进入毁灭判定集合。
6. 所有毁灭结果完成权威结算后，死亡之翼方当前回合立即结束，不能再进行普通移动或吃子。

### 被将军时发动

- 死亡之翼方当前正被将军时仍可发动“毁灭”。
- 毁灭结算完成后立即重新检查全部将军关系。
- 若全部将军威胁均已解除，则视为成功脱险，并按技能规则结束本回合。
- 若仍存在任一合法将军威胁，则由于技能已经结束当前回合且未完成合法应将，直接结算死亡之翼方失败。

### 设计与表现

- “毁灭”不是劣势补偿器，而是整局一次的末日按钮；玩家可以在优势、均势或劣势下自行判断是否值得摧毁棋盘结构。
- 50%为逐棋独立判定，不改成“双方固定各死一半”；因此允许出现严重偏离期望的极端结果。
- 当前设计阶段评分：55/100，合理区间52–58。`player_skill_sensitivity = 中高`；`skill_gap_amplifier = false`。
- 技能介绍固定最终文案：**“我乃死亡之翼，毁灭者，万物的终结……我就是大灾变！”**

## 7. 畸变一：铁马

### 7.1 适用棋子

- 暗马位棋子第一次按位置兵种移动时适用。
- 已揭明且真实兵种为马的棋子适用。
- “骑兵”是另一项互斥畸变，因此不会与铁马叠加。

### 7.2 碾碎马腿

- 马选择一个合法日字目标时，计算唯一马腿格。
- 马腿为空：按普通马步行动。
- 马腿存在任意棋子：先对该棋执行路径碾碎，再继续完成马步。
- 路径棋无论敌友、明暗、隐身或是否拥有防御，都会先清除效果再死亡。
- 暗路径棋公开真实身份并进入被吃记录。
- 铁马可以移动到空位并仅靠途中碾碎获得击杀。
- 玩家不能选择保留马腿棋再跳过。

目标点按普通移动、普通吃子或刺杀强击结算。若最终目标以普通防御抵挡，马返回原位，但马腿棋保持死亡。

### 7.3 铁马将军

铁马对将帅存在两类威胁：

1. 将帅位于马步最终落点；
2. 将帅位于马腿格，且该方向至少有一个可完成的合法马步落点。

第二类属于路径碾碎将军。敌方将帅作为马腿被杀时触发“碾碎他们！”。

## 8. 畸变二：堡垒

- 敌方控制的棋子不能从九宫外移动、吃子或使用技能进入该方九宫。
- 判定使用行动开始前的公开控制权，不读取暗子真实身份。
- 已在九宫内的敌方棋子可以在宫内移动、吃子或离开；离开后不能重新进入。
- 暗子在己方九宫内行动后可能翻成敌色并成为内部渗透者，该结果合法。
- 隐身和强击不能绕过堡垒。
- 攻击线与将军判定可以跨越堡垒；普通棋子不能从外部落入九宫吃子。
- 将死的自动终结动画可以跨越边界，因为此时只表现已确定的终局。

堡垒只限制“从外到内”的落点，不限制路径穿越九宫边界、不限制离开，也不删除九宫内已有棋子。

## 9. 畸变三：暗影之舞

- 双方各获得一次完整“刺杀”技能。
- 次数独立、公开且一直保留到使用或对局结束。
- 非潜行者也可以使用。
- 潜行者英雄同时拥有英雄次数与畸变次数，共两次。
- 两个来源不能合并成一次强化效果；每次分别产生一段隐身和一次强击。
- 同一方上一段隐身结束前不能发动下一次。

## 10. 畸变四：战车

### 10.1 适用棋子与发动条件

- 暗车位棋子第一次按位置兵种行动时适用。
- 已揭明且真实兵种为车的棋子适用。
- 必须选择同一直线上的一个实际目标，不能以空位为目标。
- 车与目标之间必须恰好存在一枚非隐身棋子。
- 任意数量的隐身棋子不参与“恰好一枚”的计数。
- 目标仍须符合普通目标规则：暗目标始终可吃、敌方明目标可吃、己方明目标不可吃；将帅不作为普通目标，只在将军与自动终结中作为概念目标。

### 10.2 结算

1. 收集起点与目标之间的全部路径棋。
2. 对唯一非隐身路径棋和全部隐身路径棋执行路径碾碎。
3. 路径棋先清除防御、隐身等效果，再直接死亡。
4. 对最终目标执行普通吃子；刺杀强击可改为强击目标。
5. 目标普通防御成功时，车返回原位，但所有路径死亡保持生效。
6. 成功到达目标后，暗车位来源才翻开，随后结算控制权和陷阱。

路径棋可以是己方明棋。路径击杀不消耗潜行者强击次数。

### 10.3 战车将军

- 车与敌方将帅之间没有非隐身棋子：构成普通车将军；隐身棋子不阻挡。
- 恰好一枚非隐身棋子：构成战车将军，无论该棋敌友或是否拥有防御。
- 两枚及以上非隐身棋子：不构成将军。
- 唯一非隐身路径棋是进攻方将帅时，仍构成将军；若最终执行，会形成同归于尽式终局。
- 敌方必须正常应将，不能因为攻击后可能平局而忽略。
- 若无合法应对，服务器按实际攻击结果播放终结，不能一律写成“裁决”。

### 10.4 暗来源的责任归属

暗车位的路径击杀发生在来源翻开以前，因此全部击杀和终局责任归属于行动开始时的控制方。来源落地后即使倒戈，也不追溯改变路径击杀结果。

## 11. 畸变五：亲征

- 双方将帅解除九宫限制，可在整个棋盘沿横线或竖线移动任意距离。
- 路径必须没有阻挡；隐身棋子不阻挡路径，但其所在格仍不能作为落点。
- 将帅可以离开九宫、跨河并进入敌方半场。
- 只检查最终落点是否受攻击；途中经过受攻击空位不影响合法性。
- 将帅获得车的直线攻击范围，可以远距离将军。
- 将帅不能把敌方将帅当作普通棋子直接吃掉，仍通过将军、将死和裁决结算。
- 将帅仍不能停在敌方攻击范围内或与敌方将帅形成无法解释的互相攻击状态。
- 将帅踩中猎人陷阱时可被伏击杀死。
- 战士将帅离开九宫不获得普通防御，只保留铁甲防御。

## 12. 畸变六：骑兵

### 12.1 升级目标

棋盘创建时，把双方五个兵位中从各自视角由左到右的第 1、第 3、第 5 个位置上的暗子标记为骑兵。由于位置对称，坐标为：

- 黑方：`(0,3)`、`(4,3)`、`(8,3)`；
- 红方：`(0,6)`、`(4,6)`、`(8,6)`。

升级附着于具体棋子 ID 并公开显示。揭开后无论真实颜色为何，升级都随该棋转交给新的控制方。

### 12.2 混合走法

骑兵每次行动可以选择：

1. 当前棋种原本的走法；或
2. 马的日字几何，并同时遵守马腿及当前棋种的方向、区域和安全限制。

“共同限制”不要求一步同时满足两种几何形状，也不把炮架等原棋种专属吃子机制套到马步上。

- 暗骑兵当前按兵位身份处理，只能使用四个前向马步，不能向后方或后侧落点移动。
- 揭开为兵/卒后，前进方向按真实颜色计算，过河后仍不能用马步后退。
- 揭开为车、马、炮、相、象、仕或士后，不存在兵卒方向限制，可使用完整八方向马步。
- 所有马步都受蹩马腿限制；“铁马”与“骑兵”互斥，不会获得碾碎能力。


## 12A. 宿命畸变：时光之末（End Time）

### 12A.1 解锁、替换与定位

- 宿命 ID：`end_time`；显示名：**时光之末**。
- 仅当双方所选英雄恰为**诺兹多姆与姆诺兹多**（阵营顺序不限）时，作为隐藏宿命候选解锁；仍遵循“外层先抽中传说，再进入传说内部候选池”的宿命规则。
- 宿命实际触发后，双方第一个正式行棋回合各在普通 60 秒基础上增加 15 秒，即 75 秒。
- 该宿命不把两名英雄当作棋盘本体直接参战。宿命期间：
  - 诺兹多姆普通技能“回溯”被禁用并由“时光勇士 + 时光沙漏”替代；
  - 姆诺兹多普通技能“扭曲时间线”被禁用并由“无限龙军团 + 时空扭曲炸弹”替代。
- 普通对局未触发“时光之末”时，两名英雄继续使用 6B、6C 的普通技能规则；宿命机制不得反向覆盖普通英雄平衡基线。
- “时光之末”当前只冻结机制与规则，不包含专属揭示动画美术；动画视觉仍属于有意暂缓项。

### 12A.2 诺兹多姆阵营：五名时光勇士

- 诺兹多姆阵营**真实身份属于本阵营的五枚兵/卒棋子**，从开局起拥有隐藏的“时光勇士”身份。
- “时光勇士”绑定真实棋子身份，不绑定五个兵/卒初始位置；不得把诺兹多姆的祝福错误赋给揭开后属于姆诺兹多阵营的棋。
- 暗置期间不得公开特殊标记、piece id、真实身份或任何能够反推出兵/卒身份的信息。
- 一枚时光勇士首次因正常揭示或“被吃后揭示”而公开真实身份后，视为**已现身**；从此公开显示“时光勇士”状态。
- 被吃时才首次揭示的时光勇士同样算已现身，即使此时已经死亡，后续仍可被时光沙漏复活。
- 从未揭示过真实身份的暗置时光勇士不进入沙漏作用集合。
- 时光勇士不获得额外移动、攻击、吃子、防御、速度或行动次数强化；宿命专属收益仅来自沙漏回归/复活体系。
- 每枚时光勇士的**时间锚点**为该具体棋子在本局开局完成随机摆放后实际所在的格子。锚点由权威端从开局保存，但在该勇士现身前不得向玩家泄露其身份映射。

### 12A.3 诺兹多姆阵营：时光沙漏 ×5

- 诺兹多姆阵营整局共有 **5 次“时光沙漏”**使用次数。
- 只能在诺兹多姆阵营自己的正式行棋回合开始、尚未移动任何棋子之前发动；发动后继续正常进行该回合。
- 权威终局一旦已经结算，不能再用沙漏翻案。

每次沙漏严格按以下顺序结算：

1. **锁定候选集合**：以发动瞬间为准，取全部已经现身的时光勇士，包括当前存活者和已死亡者。
2. **检查时间锚点**：若某勇士的锚点在发动瞬间被任意棋子占据，或该格正处于“时空扭曲”，该勇士本次回归失败；其他勇士独立判定，不受其影响。
3. **群体回归**：所有判定成功的已现身时光勇士同时回到各自开局锚点；死亡者复活后回到锚点，存活者从当前位置返回锚点。
4. **净化战场**：清除棋盘上全部“时空扭曲”；因这些扭曲产生且尚未结算的“时间崩坏”同步解除。
5. **无限龙重新装填**：所有此时仍然存活、已经现身的无限龙军团棋子，把炸弹弹药补充至 1 枚；弹药上限始终为 1，不进行累加。

补充边界：

- 沙漏只回溯诺兹多姆阵营的上述宿命对象；**姆诺兹多阵营已经发生的死亡、棋子位置、揭示、损失和其他结果不因沙漏恢复**。
- 已经现身的时光勇士复活后保持**明棋**；玩家已经得到的信息不能被时间回溯抹除。
- 被锚点占据或被扭曲封锁而本次回归失败的勇士仍保留已现身身份；本次净化后，后续沙漏若锚点重新合法，仍可再次尝试回归。
- 第 5 次沙漏结算后仍执行第 4、5 步；因此存活且已现身的无限龙会获得最后一次重新装填。此后再产生的时空扭曲已没有新的沙漏可以统一清除，天然进入宿命的最终阶段。

### 12A.4 姆诺兹多阵营：五名无限龙军团

- 姆诺兹多阵营**真实身份属于本阵营的五枚兵/卒棋子**，从开局起拥有隐藏的“无限龙军团”身份。
- 该身份同样绑定真实棋子身份，不绑定兵/卒初始位置；暗置期间不得泄露身份。
- 一枚无限龙因正常揭示或“被吃后揭示”公开真实身份后，视为已现身；只有**已现身、仍存活并由姆诺兹多阵营控制**的无限龙才能投放炸弹。
- 无限龙死亡后不通过宿命机制复活；死亡无限龙不会在之后的沙漏结算中获得炸弹补充。
- 每名符合条件的无限龙炸弹弹药上限为 **1 枚**。首次现身且存活时拥有 1 枚；沙漏只把仍存活且已现身的无限龙补充至 1 枚，不允许囤积 2 枚或更多。

### 12A.5 时空扭曲炸弹

投放窗口与全军限制：

- 只能在姆诺兹多阵营自己的正式行棋回合开始、尚未移动任何棋子之前投放。
- 每个姆诺兹多阵营回合，**全军最多投放 1 枚**，不是每条无限龙各投一枚。
- 投弹不取代本回合正常走棋；炸弹结算后仍可进行正常行动。
- 必须选择一名已现身、存活、当前由姆诺兹多阵营控制且拥有 1 枚弹药的无限龙作为施放者；投放后该施放者弹药变为 0。

射程：

- 目标格与施放者当前格满足曼哈顿距离 `|dx| + |dy| <= 3`。
- 不能选择施放者自己所在格。
- 棋子和暗子不阻挡投放路径；这是范围能力，不按车/炮等路径规则计算。
- 可以选择空格、诺兹多姆方棋子所在格、将/帅所在格、时光勇士时间锚点，以及其他姆诺兹多方棋子所在格。
- **已经处于“时空扭曲”状态的格子不能再次成为炸弹目标**；不叠层、不刷新、不重复消耗炸弹。该格被沙漏净化后，未来可以重新投放。

### 12A.6 时空扭曲区域

- 炸弹结算后，目标格获得持续存在的“时空扭曲”区域，直到被时光沙漏统一清除；没有自然回合数衰减。
- 姆诺兹多阵营棋子不受己方时空扭曲的进入限制或时间崩坏伤害。
- 诺兹多姆阵营棋子**不能主动把空的时空扭曲格作为普通移动落点**。
- 如果时空扭曲格上存在姆诺兹多阵营棋子，诺兹多姆阵营仍允许按正常规则通过**吃掉该棋**进入该格；成功落位后立即获得“时间崩坏”。因此时空扭曲不能给姆诺兹多方棋子制造绝对不可吃的防御格。
- 当前确认的限制针对“落点/占据”而不是新增路径阻挡物；不得把时空扭曲自动当成实体棋子或炮架。
- 时空扭曲可以覆盖时光勇士的时间锚点；沙漏发动时先检查锚点，因此该勇士**本次回归失败**，随后该扭曲才被净化。

### 12A.7 时间崩坏

诺兹多姆阵营棋子在以下任一情况立即获得“时间崩坏”：

1. 姆诺兹多的时空扭曲炸弹直接命中该棋当前所在格；
2. 该棋通过合法吃子进入一个已有的时空扭曲格。

结算规则：

- “时间崩坏”绑定该棋当前所在的扭曲格。
- 到该棋获得该状态之后，**诺兹多姆阵营下一次正式行棋回合结束时**，若该棋仍停留在对应时空扭曲格，则该棋直接死亡。
- 若该棋在期限内成功离开对应扭曲格，“时间崩坏”立即解除。
- 若在死亡结算前发动时光沙漏并清除了对应扭曲，“时间崩坏”同步解除。
- 将/帅同样可以获得时间崩坏；若期限结束时仍无法脱离并因此死亡，按将/帅死亡产生权威终局。

### 12A.8 战略结构与实现边界

- 本宿命设计目标不是把两名普通英雄技能继续堆到更高评分，而是形成阵营级时间战争：
  - 诺兹多姆偏中期，通过有限的 5 次群体回归/复活维持持续作战；
  - 姆诺兹多偏后期，通过无限龙军团、锚点封锁、时间崩坏和持续污染逐步侵蚀棋盘。
- 诺兹多姆方应有动机优先猎杀无限龙；姆诺兹多方应有动机保护无限龙、污染锚点并逼迫提前消耗沙漏。
- 不再给时光勇士追加额外行动或战斗强化；不再给本宿命追加新的能力，除非真实试玩显示明确结构性失衡。
- 当前设计阶段重点观测：平均沙漏使用次数、成功回归/复活次数、无限龙平均存活数、第 5 次沙漏后剩余对局回合数。
- 当前 GitHub 固定检查点仅有宿命候选接口和 75 秒常量，**“时光之末”的具体目录、状态模型、动作、结算和测试尚未实现**。

## 12B. 畸变七：混乱

> **实现状态：**规则已确认；当前设计阶段评级 95/100，稀有度为传说；当前 GitHub 检查点尚未实现。

### 12B.1 核心阵营刷新

- 每个玩家正式回合开始时，所有仍未翻开的暗子分别在权威端独立刷新一次秘密阵营：50%红方、50%蓝方。
- 刷新结果对双方均不可见，也不在棋面显示任何阵营标识。
- 每枚暗子的本轮秘密阵营持续到下一次“混乱”刷新，或该暗子先行揭开/死亡。
- 暗子真实兵种身份不因刷新改变。

### 12B.2 翻开前控制方式不变

- “混乱”**不改变基础揭棋中暗子翻开前的控制规则**。
- 玩家仍按普通对局既有规则控制自己半场内可操作的暗子；不能通过选中、点击、可移动性等方式测试秘密阵营。
- 这一条是基础规则保持不变，不作为“混乱”的额外强化或评分来源。

### 12B.3 揭示与锁定

- 暗子因正常移动而揭开时，同时公开真实兵种与该回合已经秘密确定的当前阵营。
- 一旦正常揭开，该棋阵营永久锁定，并退出后续“混乱”阵营刷新。
- 暗子若在揭开前被吃/直接摧毁，仍按普通揭棋死亡规则公开真实兵种，但**不额外公开它死亡前的秘密阵营**。
- 因此玩家仍可继续推理剩余真实兵种池，但不能通过己方已损失棋子数量推算剩余暗子中还有多少“己方阵营棋子”；红蓝暗子数量不守恒。

### 12B.4 与其他畸变

- 每局最多只生效一个畸变；宿命畸变同样占用这唯一畸变位置。
- 因此“混乱”无需与“时光之末”或时间战士额外建立特殊互斥表；两者不会在同一局同时生效。

### 12B.5 设计评级

- 当前设计阶段评级：**95/100｜传说**。
- 该分衡量对规则结构的影响，不代表任何一方获得95%的胜率或稳定优势。
- 主要影响来自：覆盖全部未揭暗子、每回合持续刷新、阵营守恒被打破、阵营信息长期隐藏、揭示时才固定阵营，以及对权威隐藏状态/联机同步/推理结构的高耦合。

## 13. 路径碾碎统一模板

铁马与战车共用同一服务器内部效果，但各自拥有不同的发动几何：

```ts
interface CrushContext {
  sourcePieceId: string;
  actingSide: Side;
  cause: "iron_steed" | "war_chariot";
  pathPieceIds: string[];
}
```

对每枚路径棋按棋盘行进顺序执行：

1. 清除普通防御、隐身和其他可移除效果；
2. 公开暗子的真实身份；
3. 从棋盘移除并写入死亡/被吃记录；
4. 记录公开动画事件；
5. 将帅死亡只做标记，不提前中断本次原子行动。

路径碾碎可以杀死将帅，且不受刺杀“不能以将帅为目标”的限制，因为将帅不是强击的选择目标。

## 14. 权威行动结算管线

现有 `applyAuthoritativeMove` 应拆为“计划—验证—结算”三层，避免通过反复模拟误读秘密身份。

### 14.1 计划

```ts
interface ActionPlan {
  actionKind: "move" | "assassination" | "forced_defense";
  actingSide: Side;
  sourceId: string;
  from: Position;
  to: Position;
  movementMode: "native" | "cavalry_horse" | "iron_steed" | "war_chariot";
  pathPieceIds: string[];
  targetId?: string;
  useStrongStrike: boolean;
}
```

计划层只读取公开数据，不得根据暗子真实身份决定按钮、提示或合法落点。

### 14.2 验证

依次验证：

1. 房间阶段、行动方、版本号和幂等 ID；
2. 来源控制权和技能次数；
3. 移动几何、路径、马腿、目标资格和堡垒；
4. 隐身目标与路径的特殊占位；
5. 使用公开状态模拟行动后，检查是否无故让己方存活将帅受攻击；
6. 铁马或战车明确碾死己方将帅的行动属于允许产生终局的特殊行动，不以普通 `SELF_CHECK` 拒绝。

### 14.3 结算

一次玩家命令严格按下列顺序原子执行：

1. 消耗技能次数并创建必要的刺杀状态；
2. 执行铁马或战车路径碾碎；
3. 结算最终目标：强击、普通吃子或普通防御；
4. 攻击者落位或因防御返回原位；
5. 成功落位的暗来源揭开并更新控制权；
6. 应用或解除隐身、普通防御、骑兵等运行时效果；
7. 成功落位后检查并触发一层陷阱；
8. 检查双方将帅最终存活状态；
9. 无将帅直接死亡时判断背刺及铁甲防御；
10. 判断普通将军、裁决和无处可逃；
11. 递减刺杀持续时间和陷阱持续时间；
12. 切换或恢复回合并把版本号增加一次。

被普通防御弹回时，步骤 5 的来源揭示、目标点陷阱和区域进入/离开效果全部跳过；步骤 2 已经发生的路径死亡不回滚。

## 15. 将军与终局判定

### 15.1 统一攻击定义

`isSquareAttacked` 不能再只检查传统棋子几何。它必须回答：“按照当前公开攻击规则，进攻方是否能够使该将帅死亡或进入既定自动终结？”堡垒允许攻击线和将军跨墙属于明确的检查特例，即使普通棋子不能实际落入九宫吃子，也仍纳入攻击判断。

因此攻击来源包括：

- 普通明棋攻击；
- 铁马把将帅作为最终马步目标；
- 铁马把将帅作为马腿路径棋；
- 战车隔一枚非隐身路径棋攻击将帅；
- 战车把将帅作为路径棋碾碎；
- 亲征将帅的车式攻击。

即使执行攻击会同时杀死进攻方将帅并导致平局，仍属于有效将军。平局是有效终局，受将方必须应对。

### 15.2 直接死亡矩阵

整次行动完成后统一检查：

| 红帅 | 黑将 | 结果 |
|---|---|---|
| 存活 | 存活 | 继续检查背刺、裁决或无处可逃 |
| 死亡 | 存活 | 黑方胜；若红方自己路径碾死红帅则为“乱杀” |
| 存活 | 死亡 | 红方胜；若黑将为敌方路径棋则为“碾碎他们！” |
| 死亡 | 死亡 | “两败俱伤”，平局 |

若将帅是最终将死目标而不是路径棋，沿用“裁决”。

### 15.3 已确认终局显示

| 规则名 | 原因代码 | 结果或播报 |
|---|---|---|
| 背刺 | `ambush` | `暗中潜行，破影而袭！您获得胜利！` |
| 裁决 | `checkmate` | `圣光的正义终结了敌人！您获得胜利！` |
| 无处可逃 | `stalemate` | 无合法走法的一方失败 |
| 臣服 | `resign` | `对方已臣服于您，获得胜利！` |
| 虚空放逐 | `disconnect` | `对方意外遭遇阿克蒙德，并不慎触怒了他。已被流放至扭曲虚空。` |
| 伏击 | `trap_ambush` | `猎物已踏入陷阱！伏击得手，红方／黑方获得胜利！` |
| 碾碎他们！ | `crush_them` | `碾碎他们！您获得胜利！` |
| 乱杀 | `rampage` | 仅碾死己方将帅，发动方失败 |
| 两败俱伤 | `mutual_destruction` | 双方将帅在同一次行动中死亡，平局 |

“乱杀”和“两败俱伤”尚未指定完整句式时，客户端只显示规则名和通用的失败/平局结果，不得自行增加世界观文案。

## 16. 动画与公开事件

现有 `LastMove` 只能记录一个目标，无法表达路径多杀、弹回和陷阱。建议改为服务器生成的有序事件：

```ts
type ActionEvent =
  | { kind: "move_started"; pieceId: string; from: Position; to: Position }
  | { kind: "effect_removed"; pieceId: string; effect: string }
  | { kind: "path_crushed"; pieceId: string; at: Position; identity?: SecretIdentity }
  | { kind: "target_captured"; pieceId: string; at: Position; identity?: SecretIdentity }
  | { kind: "barrier_bounce"; attackerId: string; defenderId: string }
  | { kind: "piece_revealed"; pieceId: string; identity: SecretIdentity }
  | { kind: "trap_triggered"; trapOwner: Side; at: Position; victimId: string }
  | { kind: "terminal"; outcome: GameOutcome };

interface ResolvedAction {
  actionId: string;
  revision: number;
  actingSide: Side;
  events: ActionEvent[];
}
```

客户端严格按事件顺序播放，不自行重新计算击杀、揭示或终局。终结动画播放完毕后才显示最终文案。

## 17. 联网数据边界

### 17.1 所有人可见

- 已公开的英雄选择；
- 当前畸变；
- 英雄/畸变技能剩余次数；
- 骑兵、普通防御、铁甲防御和隐身标记；
- 隐身剩余己方回合数；
- 陷阱触发事件，但不公开未触发陷阱；
- 有序行动事件和终局结果。

### 17.2 仅本人可见

- 自己尚未公开的英雄选择；
- 自己布置的陷阱坐标、叠层和剩余有效期。

### 17.3 仅服务器可见

- 全部未揭暗子真实身份；
- 双方尚未同时锁定时的英雄选择；
- 双方全部陷阱权威状态；
- 随机源和防重放记录。

原 `publicRemoteRoom(room)` 应升级为 `playerRoomView(room, playerId)`；旁观视图必须隐藏双方陷阱。

## 18. 必须新增的测试组

### 18.1 流程与保密

- `MODE-*`：四种开关组合都能进入正确阶段。
- `HERO-SELECT-*`：同选合法，双方锁定前不泄露。
- `MUTATION-*`：只抽一项、结果公开、测试随机可复现。
- `TRAP-SECRET-*`：敌方和旁观者永远看不到未触发坐标；本人刷新可恢复。

### 18.2 英雄

- `HUNTER-*`：半场、脚下、叠层、一次一层、前9回合致死、第10–12回合剩余层控制、到期失效、控制权前后双判定、将帅伏击。
- `ROGUE-*`：发动目标、首次移动/立即强击二选一、一回合隐身、提前现身、强击清除效果、两次来源隔离。
- `WARRIOR-*`：前两枚不同棋、离宫触发、名额不回补、两步衰减、弹回、将帅铁甲与额外应将。
- `QIN-LONG-*`：15完整回合前不触发、解锁后15%回合判定、雨夜只持续当前回合、合法将军立即终局、无将军则正常结束。
- `MUROZOND-*`：目标必须是对手上一手仍存活棋、只退回该棋、不复活被吃目标、只能控制同一棋合法重走、无合法着法时不可发动、发动后己方不再走棋。
- `NOZDORMU-*`：每局一次、己方回合前10秒窗口、被将军时禁用、完整快照恢复、信息记忆不恢复、必须同棋重走、时间上限、不能吃子/不能将军。

### 18.3 畸变

- `IRON-STEED-*`：空马腿、敌友暗明隐身马腿、空目标移动碾碎、目标防御、路径将帅。
- `IRON-WALL-*`：外部禁止进入、内部移动、渗透者离开后不能返回、强击不能突破、跨墙将军。
- `SHADOW-DANCE-*`：双方各一次、潜行者两次、不能并行潜行。
- `WAR-CHARIOT-*`：零/一/二枚普通路径棋、任意隐身路径、路径防御无效、目标防御有效、三种将帅结果。
- `EXPEDITION-*`：离宫、跨河、远距离移动、只检查落点、远程将军、陷阱死亡。
- `CAVALRY-*`：六个固定升级 ID、暗兵前向四马步、蹩马腿、揭示转移、非兵完整马步。

### 18.4 交叉与终局

- `CROSS-ROGUE-WARRIOR-*`：隐身后普通刺杀弹回并现身、强击破防。
- `CROSS-CRUSH-ROGUE-*`：路径碾碎不消耗强击，最终目标可使用强击。
- `CROSS-CRUSH-WARRIOR-*`：路径防御无效、目标防御仍有效。
- `CROSS-HUNTER-*`：陷阱晚于落位揭示、早于背刺和裁决。
- `END-RAMPAGE-*`：仅己方将帅死亡判负。
- `END-MUTUAL-*`：双方将帅死亡判和。
- `END-CRUSH-*`：敌方将帅作为路径棋时使用专属播报。
- `CHECK-DRAW-THREAT-*`：会导致两败俱伤的攻击仍构成将军，不能误判为裁决。

## 19. 推荐实现顺序

为降低一次改动范围，按以下顺序实施：

1. 扩展 `GameOutcome`、有序事件和按玩家过滤的房间视图；
2. 加入模式开关、英雄选择和畸变抽取，不改变走棋；
3. 实现通用棋子效果框架与刺杀；
4. 实现战士防御和猎人陷阱；
5. 实现骑兵与亲征两项移动扩展；
6. 实现统一路径碾碎，再接入铁马和战车；
7. 重写攻击/将军查询以覆盖路径终局；
8. 接入动画事件和全部终局文案；
9. 完成测试矩阵后才修改联机界面；
10. 秦龙、姆诺兹多、诺兹多姆作为已确认但未实现的英雄增量，进入实现前分别先补状态模型和定向测试；“时光之末”作为已确认但未实现的宿命增量，也必须单独补秘密身份、沙漏结算顺序、炸弹射程、锚点封锁、时间崩坏、第五次沙漏终局阶段等定向测试。除非X明确调整优先级，本条不覆盖当前交接状态中“累计断线60秒”为下一实现阶段的决定。

每一步都必须保证基础模式回归测试通过，不要把六项畸变一次性塞入现有 `movementGeometryLegal`。

## 20. 验收标准

进入功能编码前，本规格满足：

- 十名当前英雄与七项标准畸变的已确认玩法分支均可从本规格和 `BALANCE_AND_RULE_UPDATES.md` 恢复；后七名英雄仍须明确标记为“规则确认、代码未实现”；
- 关闭新模式时与 v0.4.0 行为完全一致；
- 任意客户端都无法从落点提示、英雄锁定或房间推送获得暗子及陷阱秘密；
- 所有复合行动由服务器生成一个有序事件序列；
- 直接杀将、背刺、裁决和陷阱不会产生两个互相冲突的终局；
- 平局能够在类型层表达，不伪造胜方；
- 所有公开效果都由棋子 ID 跟踪，控制权改变不会丢失或复制效果。
