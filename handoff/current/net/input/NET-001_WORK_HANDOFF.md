## 0. 给 Work 的执行摘要

《乐子象棋》未来**正式发布主要面向微信生态，优先研究微信小游戏形态，可能仅保留微信端**。既有 Android APK 与独立网页版继续承担开发与技术测试职责，并保留未来分别办理适用手续后发布的可能，但**不得默认**三端同时上线、同时长期维护。游戏规则与服务端权威结算必须与平台 UI 解耦，后端需具备微信端接入的可移植性。

本阶段优先推进 **NET-001（境外低成本联机可行性验证）**：面向**中国大陆真实网络**验证 Cloudflare 与香港节点方案的可达性、往返延迟、波动、稳定性、WebSocket 保活/重连；尽力将小规模测试的每月基础设施预算压到 **人民币 50 元以内**。账密、登录、测试邮箱验证、好友房间、陌生人匹配、实时对局、局面权威裁决与保存/恢复属于联网系统设计范围，但不能假装本阶段都已做完。

**APP 备案及适用网络游戏出版审批**是**项目完成、准备正式上线时**再组织落实的任务；当前测试阶段不将其列为开发交付目标。此“暂缓”并不表示存在豁免，也不授权无需相应程序就向不特定公众进行运营。**微信平台防沉迷**未来作为主要接入方向，服务端需配合；不能假设微信的防沉迷能力自动覆盖 APK 或独立网页。

## 2. 明确未锁定、尚不可当作事实的事项

- **未定生产后端服务商**：Cloudflare Workers / Durable Objects / D1 目前是**优先候选**，并非已经证明适合中国大陆用户，也非正式选型结论。
- **香港节点是备选**：提供商、地域、带宽、线路、计费周期、优惠价格、续费价格均未最终确定。
- **未进行真实线路实测**：中国大陆三大运营商的端到端延迟、连接质量、丢包、成功率、稳定性均无有效测试报告。
- **成本未验证**：先前讨论过的“Cloudflare 0 元起”“香港机约 40 多元/月”“0–15 元/月”等均是探索性参考值，需核对最新条款、超额计费、WebSocket/数据库费用及国内实际可访问性。
- **未确定账号体系细节**：微信登录、账号绑定、访客、邮箱找回、防刷、黑名单及跨端账号关联都需要在现有项目状态核验后细化，不能直接引入大规模复杂系统。
- **未落实微信端功能/审核能力**：微信小游戏登录、网络域名配置、实名/防沉迷可复用程度及平台条件应查官方最新资料；不能推断微信可以自动处理所有合规事项。
- **未获得任何公开运营的合规结论**：服务器在境外、免费、个人身份或不盈利均不能自动认定无备案、审批或其他义务；本交接只设定当前开发任务范围。
- **测试验收阈值尚非用户锁定值**：曾提出“95% 操作 RTT 小于 500 ms、持续 WebSocket 60 分钟、网络恢复后尽量 5 秒重连”等，属于待讨论的参考验收指标。

## 3. 当前期望的技术分层（规划建议，非已实现）

1. **客户端层**：当前 APK 和网页可做功能测试；未来微信小游戏适配层只承担展示、输入、账号入口与通信适配。
2. **统一通信层**：HTTPS API + WebSocket；接口与消息协议不与 Android 专用组件绑定。
3. **服务端权威对局层**：负责走子合法性、暗子信息访问控制、英雄/畸变事件、回合状态、终局与结算；客户端不自行裁定比赛结果。
4. **匹配与房间层**：好友对局、陌生玩家匹配、房间生命周期、断线恢复、超时与异常会话。
5. **身份与数据层**：稳定的内部用户标识，认证方式可替换；持久化账户资料、战绩、必要对局快照或事件日志。
6. **未来平台能力层**：微信身份、防沉迷与可能的其他平台账号入口作为可插拔适配，服务端统一执行与游戏安全相关的限制。

架构要求：**不改动已确定的游戏规则，复用原有引擎和现有接口**；先审计目前仓库实现程度，再判断哪些分层已有、哪些必须新增。

## 4. 优先对比候选（等待验证）

### 4.1 Cloudflare 组合（候选 A）
- 可能组成：Workers（入口/API）、Durable Objects（有状态房间/实时连接）、D1（结构化数据），具体按已存代码和产品限额选择。
- 预期优势：开发测试固定成本低，免自行维护传统 VM 的操作负担。
- 核心风险：普通全球网络对中国大陆各运营商的性能差异；中国大陆网络与 Cloudflare 中国网络不是一回事，不能推断低延迟；免费计划对连接/请求/运行时间/存储/写入可能有单独限制。
- 适配检查：微信小游戏的合法通信域名、TLS、WebSocket、回源/IP 变化、证书与平台要求。

### 4.2 香港境外节点（候选 B）
- 可能组成：轻量 VPS 上提供 API、WebSocket、匹配/房间、数据库；先用小规模 PoC，避免一次性购入长期套餐。
- 预期优势：运行环境和网络出口更可控。
- 核心风险：中国大陆跨境回程线路差异、带宽限额、晚高峰抖动、续费成本、运维与安全责任。
- 价格核对：明确人民币月成本、账单币种、优惠和续费、流量费用、地域与套餐限制；不要仅依据促销首月价做决策。

### 4.3 备选区域
- 日本节点或其他境外地区可作为测量备选，但不能凭“地理距离近”推断端到端体验更好。

## 5. 注册与账号策略

- 小规模测试只做必要的登录能力；电子邮件验证码可行，但**是否必要、何时接入**应服从 NET-001 先验证网络的顺序。
- 若采用邮件验证码：服务器生成、设置短有效期与频率限制，验证后下发安全会话；不在客户端存储邮件服务私钥；需防滥发与滥用。
- 未来微信正式平台优先评估微信授权登录；以内部账号 ID 隔离外部身份来源，避免把邮箱作为全部玩家必须绑定的主键。
- 不要把邮箱验证码等同于网络游戏的实名验证或防沉迷机制。

- 在不改变游戏业务逻辑的前提下，设计一个与未来微信兼容的 **HTTPS ping/echo + WebSocket echo** 测试最小服务。

### NET-001.3：成本与配额核验
- 依据最新官方文档计算预估场景（例如几十、数百、数千活跃玩家），分别列出请求、WebSocket 连接、数据库、发信、带宽和存储成本。
- 区分“免费额度内可行”“超额后自动收费”“超额后服务受限”，并核验域名、DNS/TLS、微信平台接入成本。
- 不未经用户同意购买收费方案、不自行绑定付款方式。

### NET-001.4：架构决策提案
- 将实测结果与成本、运维风险、微信兼容性一并对照，形成一份**推荐方案 + 回退方案 + 不确定项**。
- 先完成必要论证，再以最小改动逐步接入账户/房间/匹配/实时权威对局，避免先构建过度复杂的账户体系。
