# MODE-SCORE-MODEL-001：受控机制验收

本工具落实原揭棋 H11 窗口 B 的正式计数，记录 H14/H11 的实际机制轨迹，并运行已交接的 JF01～JF09。它不产生英雄净强度 H、畸变影响度 I 或偏向 B 的真实评分，不批准经验参数，不解除普通象棋/半混乱的适配保护。

## 实现

- B 成功在现有权威技能事务内将黑方正式完成计数1→2；不调用黑方普通开始、主行动或结束结算。A不额外计数。重复 actionId 由现有权威入口处理。
- `src/mechanism-observer.ts` 只在显式同步捕获期间保存脱离原状态且冻结的来源快照。默认不开启、不额外抽随机数或读取时钟、不向 GameState 增加研究字段。普通回合结束钩子记录正式计数入账时的阶段快照；完整后置效果以权威最终快照为准。
- `fixture-runner.ts` 从真实房间创建、英雄锁定、猜拳及单次先后手交换开始，使用合法 Fisher-Yates 抽取实现指定身份池与 `jian_xie` 条件。6/12点资源来自实际正式回合，不直接注入。
- 每次提交后的显式 `advanceRemoteRoomTime` 模拟现有 `BluetoothHostRoom.views()` 的正常时钟推进。这一步属于执行器的产品流程，日志观察不推进阶段。特别是B跳过后仍为黑方，正常视图tick启动黑2时钟。
- 85字段只在权威研究记录中导出；公共/A私有/B私有日志直接调用现有产品权限投影。秘密目标、身份与失败尝试不会发给公共或对手投影。各文件仅供相应权限的研究审查，绝不作为玩家策略输入。
- 逐行JSON带顺序和哈希链，清单记录文件哈希、长度和事件数。近期history超过8及洗牌清空不会删除独立记录。私有与权威日志文件权限为0600。

## 验证

先运行本次新增检查、有关的既有回归与网页编译，然后把真实验证结果及哈希放在输出目录的 `validation/results.json`，再运行：

```sh
node scripts/scoring/run-acceptance.ts review/scoring/2026-10-10
```

新建验证目录时，可使用 `scripts/scoring/validate.ts <output>` 一次完成上述顺序。验收导出逐fixture结果、4项补充事务/持久化轨迹、16条AC结果及已填回传合同。文件内的未执行规格属于历史输入；实际结果以输出目录的回传合同和证据为准。

固定布局、受控时钟与脚本只证明这些机制前缀。随机tape记录合法范围、语义事件键和确定取值，并可重放；它没有群体采样权重，不是完整对局或经验策略。JF01～JF09未自然终局，停止保留未知结果，不能记为和局。TX-CLOCK的超时只用于时钟负面验收，不纳入评分样本。

共同理论v0.3、评估v0.4及正式评分冻结状态保持不变。下一阶段仍需经验策略、独立采样、q估计及畸变编码审查；不能从本次机制通过推导候选参数已确认。
